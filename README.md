# 我的训练 · 8周体态重组

纯前端、无构建的 GitHub Pages / PWA 训练记录网站。入口 `index.html`；旧中文地址自动转到新入口，保持同源本地记录。

## 使用

- 首次进入「我的」核对8周开始日期、可用器械、动作经验与加重档位。
- 训练页按日期查看上肢 / 下肢 / 核心有氧 / 恢复循环；逐组录入实际重量、次数或时长、RPE，再勾选完成。
- 输入状态与备注会即时刷新规则建议，支持疲劳、无器械、只有哑铃、只有弹力带、时间有限与不适等明确关键词；这是关键词规则，不是自然语言模型。
- 保留原主推荐，替代动作按目标、器械、难度三个分项打星。替换后原动作已记录组仍在历史里。
- 教学提供原创两阶段 SVG 示意与步骤；肌群图按实际完成动作映射估算，不是测量结果。
- 身体页按日期记录体重、腰围、大腿围；同日更新、编辑、删除，趋势按真实日期间隔绘制。
- 日历按月查看计划与历史；未来日期不能提前记录完成组或打卡。恢复日可以只打卡休息。
- 「我的」导出 / 导入完整 JSON；另可导出身体数据 CSV。导入严格校验、确认覆盖并保留一份导入前本地快照。

## 数据与兼容

`shape8w_v2` 存储个人设置、按日期的身体与训练记录。仅保存在当前浏览器，不上传，不跨设备同步。换设备或清除浏览器数据之前请导出 JSON。浏览器空间不足会显示持续警告；损坏数据不会被静默覆盖，支持导出原始文本。多个窗口同时修改时，旧窗口暂停写入并提醒，避免互相覆盖。

原 `shape8w_v1` 保持不变，首次读取时复制为旧版档案。由于旧版没有日期和逐组数据，用户需提供旧计划真实开始日期，才迁移完整日打卡；不虚构重量或次数，部分动作勾选保留在档案里。更改计划起始日不移动已保存的训练记录。

## 建议边界

目标为体态重组，不设置激进减重目标或热量缺口，不宣称局部减脂，不根据身高体重猜测最大力量。身体基本信息只作为背景；实际负重建议依赖同动作历史、RPE、训练阶段与当天状态。

不适暂停优先于其他规则。第1–2周学习，第3–7周连续两次同负重、全组达到次数上限且 RPE ≤ 8，才考虑增加最小档位（不超过当前重量5%）；第8周维持。缺失RPE、组数不足或不同负重不自动加重。计时动作不自动增加时长，替代动作使用独立历史。阈值是保守产品规则，不是医学处方。

肌群专项比例：每组总贡献为1，主要肌群权重1、次要0.5，组内归一化后累计；只统计次数型力量动作，秒/分钟动作不混算。星级：目标重合0–2、器械可用0或2、难度匹配0或1，不适时暂停选用。教学和人体图是简化示意，不是绝对标准姿势或解剖图。

背景参考：[ACSM 2026抗阻训练原则](https://acsm.org/resistance-training-guidelines-update-2026/)；[ACE动作库](https://www.acefitness.org/resources/everyone/exercise-library/)。原创提示是一般训练提示，不能替代针对个人的动作评估。

## 开发与验证

运行环境：Node.js 22+；网站本身不需要 Node 或后端。

```sh
npm install
npm test
npm run test:browser
npm run preview
```

浏览器测试使用本机 Chrome（Playwright `channel: chrome`），模拟手机触摸及不同宽度，并以 `/my-fitness-plan/` 子路径测试。截图默认写入被忽略的 `test-results/`，可通过 `ARTIFACT_DIR` 指定目录。预览地址为 `http://127.0.0.1:4173/my-fitness-plan/`。

测试涵盖日期边界、规则优先级与加重门槛、备份校验、旧数据迁移、手机记录与持久化、教学弹窗、日历、趋势、导出导入、离线重开、计时器、存储错误和响应式溢出。自动测试为 Chromium 手机模拟；未在真实 iPhone / Safari 设备验证。

GitHub Pages 从 main 根目录发布，无需 API 密钥。服务工作线程只缓存本应用文件，不读取或上传训练存储；首次完整联网打开后可以离线。修改缓存文件后同步更新 `sw.js` 中的 CACHE 版本，确保旧缓存被清理。
